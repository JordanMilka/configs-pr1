# Эмулятор командной оболочки (вариант 8, этапы 1–5)

## 1. Общее описание

Учебный проект по дисциплине «Конфигурационное управление».
Разрабатывается эмулятор языка оболочки ОС, работа которого
максимально похожа на работу в командной строке UNIX-подобной
системы.

| Этап | Что сделано |
| --- | --- |
| 1. REPL | Графический интерфейс, парсер ввода с переменными окружения, команда `exit`. |
| 2. Конфигурация | Параметры командной строки, отладочный вывод, стартовый скрипт. |
| 3. VFS | Виртуальная файловая система из ZIP-архива в памяти, base64 для двоичных данных, ошибки загрузки. |
| 4. Основные команды | Логика `ls` и `cd`, команды `cat` и `uniq`, приглашение с текущим каталогом. |
| 5. Дополнительные команды | Команды `chown` и `rm`, изменяющие VFS только в памяти, и справка `help`. |

Что реализовано:

- графический интерфейс на библиотеке `tkinter` (входит в
  стандартную поставку Python);
- заголовок окна `Эмулятор - [username@hostname]` по данным реальной ОС;
- парсер ввода с раскрытием переменных окружения реальной ОС
  (`$HOME`, `${HOME}`);
- команды `ls`, `cd`, `cat`, `uniq`, `chown`, `rm`, `help`, `exit` и
  служебные команды `vfs-info` и `vfs-tree`;
- сообщения об ошибках: неизвестная команда, неверные аргументы и
  ключи, несуществующие пути, ошибка разбора, ошибка загрузки VFS;
- параметры командной строки `--vfs` и `--script`, отладочный вывод
  параметров, стартовый скрипт с остановкой на первой ошибке;
- скрипты реальной ОС (`.sh` и `.bat`) для проверки параметров,
  вариантов VFS и всех команд.

Требования к окружению: Python 3.8 или новее с модулем `tkinter`.
Внешние зависимости не используются.

## 2. Описание всех функций и настроек

### Параметры командной строки

| Параметр | Значение | Назначение |
| --- | --- | --- |
| `--vfs ПУТЬ` | путь | Путь к ZIP-архиву с VFS. |
| `--script ПУТЬ` | путь | Путь к стартовому скрипту эмулятора. |
| `-h`, `--help` | — | Справка по параметрам и выход. |

Оба параметра необязательны. При запуске эмулятор печатает значения
всех параметров, незаданный помечается «не задан»:

```
Параметры запуска:
  путь к VFS: data/nested.zip
  путь к стартовому скрипту: scripts/emulator/stage5_all.txt
```

Без `--vfs` файловая система пуста: в ней есть только корень `/`.
Приглашение к вводу показывает текущий каталог VFS: `/$` в корне,
`/home/user$` после `cd /home/user`.

### Команды эмулятора

| Команда | Описание |
| --- | --- |
| `ls [-l] [-a] [путь...]` | Содержимое каталогов и сведения о файлах. |
| `cd [путь]` | Смена текущего каталога. |
| `cat [-n] файл...` | Вывод содержимого файлов. |
| `uniq [-c] [-d] [-u] [-i] файл` | Удаление подряд идущих повторяющихся строк. |
| `chown [-R] ВЛАДЕЛЕЦ[:ГРУППА] путь...` | Смена владельца и группы. |
| `rm [-r] [-f] [-v] путь...` | Удаление файлов и каталогов. |
| `vfs-info` | Служебная: источник, число каталогов и файлов, размер, вложенность. |
| `vfs-tree` | Служебная: дерево каталогов и файлов VFS. |
| `help [команда]` | Список команд с описаниями или справка по одной команде. |
| `exit` | Завершает работу эмулятора. |

`ls`, `cd`, `cat`, `uniq`, `vfs-info` и `vfs-tree` только читают VFS;
`chown` и `rm` изменяют её **только в памяти** — архив на диске не
затрагивается, а после перезапуска VFS загружается заново. Ключи
записываются одной буквой после дефиса и объединяются (`-la`);
`--` заканчивает список ключей. Длинные ключи (`--all`) не
поддерживаются. Пути бывают абсолютными (`/home/user`) и
относительными (от текущего каталога), части `.` и `..` работают как
в UNIX, выше корня подняться нельзя.

**ls** — без операндов показывает текущий каталог. Имена выводятся в
строку через два пробела, по алфавиту без учёта регистра; имена с
точки скрыты.

| Режим | Результат |
| --- | --- |
| `ls [путь]` | Каталог; для файла — его имя. |
| `ls -l` | Подробный список: тип и права, владелец, группа, размер, время изменения, имя. |
| `ls -a` | Дополнительно скрытые имена, а также `.` и `..`. |
| `ls путь1 путь2` | Файлы списком, затем каждый каталог с заголовком `путь:`. |

**cd** — без аргумента переходит в корень, при успехе ничего не
выводит. Аргумент один: `cd a b` — ошибка.

**cat** — склеивает содержимое файлов в порядке аргументов, как в UNIX.
Режимы: один файл, несколько файлов, `-n` (сквозная нумерация строк).
Двоичные файлы выводятся в виде base64, в котором хранятся в VFS.
Если хотя бы один файл не найден, ничего не выводится.

**uniq** — сравнивает только соседние строки, как в UNIX.

| Режим | Результат |
| --- | --- |
| `uniq файл` | Подряд идущие одинаковые строки схлопываются. |
| `-c` | Перед строкой выводится число повторов. |
| `-d` / `-u` | Только повторяющиеся / только неповторяющиеся строки. |
| `-i` | Регистр не учитывается. |
| `-ci`, `-cd` | Ключи можно объединять; `-d` и `-u` вместе — ошибка. |

**chown** — первый операнд задаёт владельца, остальные — пути.
Существование пользователей не проверяется (их списка нет): подойдёт
любое имя из букв, цифр, `_` и `-`, начинающееся с буквы или `_`.
Если хотя бы один путь не найден, ничего не меняется.

| Режим | Результат |
| --- | --- |
| `chown имя путь...` | Меняется только владелец. |
| `chown имя:группа путь...` | Меняются владелец и группа. |
| `chown :группа путь...` | Меняется только группа. |
| `-R` | Каталоги обрабатываются вместе с содержимым. |

**rm** — удаляет узлы из дерева VFS в памяти. Если хотя бы один
операнд недопустим, ничего не удаляется. Повторяющиеся и вложенные
операнды (`rm -r a a/b`) обрабатываются без ошибок.

| Режим | Результат |
| --- | --- |
| `rm путь...` | Удаляются файлы; каталог — ошибка. |
| `-r` | Каталоги удаляются вместе с содержимым. |
| `-f` | Несуществующие пути не считаются ошибкой; `rm -f` без операндов — не ошибка. |
| `-v` | Сообщение `удалён 'путь'` (для каталога — `удалён каталог 'путь'`) по одной строке на операнд. |
| `-rf`, `-rv` | Ключи можно объединять. |

Нельзя удалять корень, `.` и `..`, а также каталог, содержащий текущий.

**help** — без аргументов выводит все команды с кратким описанием в
два столбца, `help КОМАНДА` — использование, ключи и примечания.

**Сообщения об ошибках** (`КОМАНДА` — имя команды):

| Ситуация | Сообщение |
| --- | --- |
| Неизвестная команда | `КОМАНДА: команда не найдена` |
| Путь не существует | `КОМАНДА: путь: нет такого файла или каталога` |
| `cd` в файл | `cd: путь: не является каталогом` |
| `cat`, `uniq` для каталога | `КОМАНДА: путь: является каталогом` |
| Неверный ключ | `КОМАНДА: неверный ключ -- 'x'` |
| Лишние аргументы | `cd: слишком много аргументов`, `help: слишком много аргументов` |
| Нет файла | `КОМАНДА: не указан файл` (`cat`, `uniq`) |
| `uniq` | `uniq: лишний операнд 'путь'`, `uniq: ключи -d и -u несовместимы`, `uniq: путь: двоичный файл` |
| `chown` без операндов | `chown: не указан владелец`, `chown: не указан файл после 'имя'` |
| `chown` с неверной записью | `chown: неверный владелец или группа: 'имя:'` |
| `rm` | `rm: пропущен операнд`, `rm: невозможно удалить 'путь': это каталог` |
| `rm`, корень | `rm: невозможно удалить '/': это корневой каталог` |
| `rm`, `.` и `..` | `rm: невозможно удалить '..': нельзя удалять '.' и '..'` |
| `rm`, текущий каталог | `rm: невозможно удалить 'путь': это текущий каталог или содержит его` |
| `help` | `help: нет справки по 'команда'` |
| Аргументы у `exit`, `vfs-*` | `КОМАНДА: команда не принимает аргументов` |
| Команда VFS без `--vfs` | `КОМАНДА: VFS не подключена, задайте параметр --vfs` |
| Ошибка разбора строки | `ошибка разбора: ...` |

Переменные окружения реальной ОС раскрываются в любой команде, в том
числе в путях и записи владельца (`cd $EMU_DIR`, `chown $EMU_OWNER f`):

- `$NAME` — имя читается до первого символа, не являющегося буквой,
  цифрой или `_`; `${NAME}` — имя ограничено фигурными скобками;
- неизвестная переменная заменяется пустой строкой, одиночный `$`
  выводится без изменений;
- незакрытая скобка, пустое имя `${}` или недопустимые символы в
  имени (`${A B}`) вызывают ошибку разбора.

### Виртуальная файловая система

Источник VFS — ZIP-архив из параметра `--vfs`. Правила загрузки:

- архив открывается только на чтение и читается в память целиком,
  распаковка на диск не выполняется, архив не изменяется;
- каталоги создаются по путям записей, записи о каталогах не
  обязательны; пустой архив допустим;
- текстовый файл (корректный UTF-8 без нулевых байтов) хранится
  строкой, двоичный — строкой base64; в `vfs-tree` двоичные файлы
  помечены `[двоичный]`;
- права берутся из атрибутов Unix записи (без них — `rw-r--r--` у
  файлов и `rwxr-xr-x` у каталогов), время изменения — из даты записи,
  владелец и группа по умолчанию — `root`;
- абсолютные пути, пути с `..`, повторяющиеся пути и совпадение имени
  файла с именем каталога — ошибка формата.

Ошибки загрузки выводятся в окно эмулятора:

| Ситуация | Сообщение |
| --- | --- |
| Файл не найден | `ошибка загрузки VFS: файл не найден: ПУТЬ` |
| Неверный формат | `ошибка загрузки VFS: неверный формат архива ПУТЬ: ...` |
| Каталог вместо файла, файл не читается | `ошибка загрузки VFS: не удалось прочитать ПУТЬ: ...` |
| Небезопасный путь, дубликат, конфликт имён | `ошибка загрузки VFS: небезопасный путь в архиве: ...` |

После ошибки эмулятор продолжает работу в интерактивном режиме без
VFS, а стартовый скрипт не выполняется (его команды рассчитаны на
загруженную VFS), о чём выводится сообщение.

`python3 scripts/make_vfs.py [КАТАЛОГ]` создаёт образцы (по умолчанию
в `data`), время изменения всех записей — `2026-01-15 10:30`:

| Файл | Содержимое |
| --- | --- |
| `empty.zip` | Пустой архив. |
| `minimal.zip` | Один файл `hello.txt`. |
| `several.zip` | Четыре файла (один двоичный, `fruits.txt` с повторами) и пустой каталог. |
| `nested.zip` | Шесть уровней вложенности, скрытый `.profile`, `words.txt` с повторами, двоичный `logo.png`. |
| `broken.zip` | Текстовый файл, а не архив, — для проверки ошибки формата. |

### Стартовые скрипты эмулятора

Файл UTF-8, по команде в строке; пустые строки и строки с `#`
пропускаются. На экране отображаются и ввод (с приглашением), и вывод.
На первой ошибке выполнение останавливается, выводится номер строки
файла. Поэтому каждая ошибочная ситуация вынесена в отдельный скрипт, а
скрипты с рабочими режимами заканчиваются командой `exit`. Скрипты
лежат в `scripts/emulator/`:

| Файл | Назначение |
| --- | --- |
| `stage2_demo/error/exit.txt` | Этап 2: успешный запуск, остановка на ошибке, `exit`; работают и без VFS. |
| `stage3_all.txt` | Команды этапов 1–3 в рабочих режимах (`data/nested.zip`). |
| `stage3_empty/minimal/several/nested.txt` | `vfs-info` и `vfs-tree` для образцов VFS. |
| `stage3_error_*.txt` | Неизвестная команда, неверные аргументы, ошибка разбора, команда VFS без `--vfs`. |
| `stage4_all.txt`, `stage4_several.txt` | `ls`, `cd`, `cat`, `uniq` во всех режимах. |
| `stage4_env.txt` | Переменные `EMU_DIR` и `EMU_FILE` в путях. |
| `stage4_errors/*.txt` | Ошибки `ls`, `cd`, `cat`, `uniq`. |
| `stage5_all.txt` | Все режимы `help`, `chown`, `rm` на `data/nested.zip`. |
| `stage5_several.txt` | `chown`, `rm`, `help` на `data/several.zip`. |
| `stage5_env.txt` | Переменная `EMU_OWNER` в записи владельца. |
| `stage5_memory.txt` | Удаление почти всей VFS для проверки «только в памяти». |
| `stage5_errors/*.txt` | Ошибки `chown`, `rm`, `help`. |

### Скрипты реальной ОС

Лежат в `scripts/os/`, у каждого есть версия `.sh` (Linux, macOS) и
`.bat` (Windows). Все сначала создают образцы VFS, затем запускают
эмулятор. Если стартовый скрипт не завершается командой `exit`, окно
остаётся открытым — закройте его, чтобы перейти к следующему шагу.

| Скрипт | Что проверяет |
| --- | --- |
| `test_params` | Все сочетания параметров `--vfs` и `--script`. |
| `test_script_errors` | Ошибки стартового скрипта: остановка, файл не найден, `exit`. |
| `test_vfs_minimal/several/nested` | Минимальные VFS, несколько файлов, шесть уровней вложенности. |
| `test_vfs_errors` | Файл не найден, неверный формат, каталог вместо архива. |
| `test_stage3_all` | Команды этапов 1–3: `stage3_all.txt` и все `stage3_error_*`. |
| `test_stage4_all/env/errors` | `ls`, `cd`, `cat`, `uniq`; переменные окружения; ошибки. |
| `test_stage5_all` | Все режимы `help`, `chown`, `rm`; задаёт `EMU_OWNER`. |
| `test_stage5_errors` | По очереди все скрипты из `stage5_errors`. |
| `test_stage5_memory` | Сравнивает контрольную сумму архива до и после запусков с удалением. |

### Модули

Для каждого модуля `src/` перечислены его функции и классы.

- `config.py` — параметры и отладочный вывод: `build_parser()`,
  `parse_arguments(argv)` (возвращает `Config(vfs_path, script_path)`),
  `format_value(value)`, `format_config(config)`.
- `script.py` — `read_script_lines(path)` (при ошибке `ScriptError`),
  `is_executable_line(line)`.
- `parser.py` — переменные окружения и токены: `is_name_symbol`,
  `read_plain_name`, `read_braced_name`, `read_variable_name`,
  `expand_variables(text)`, `parse_line(line)`.
- `errors.py` — `CommandError` (ошибка команды), `ExitRequestedError`
  (запрос на выход).
- `options.py` — `read_cluster(name, argument, allowed)`,
  `parse_options(name, arguments, allowed)`: ключи и операнды.
- `paths.py` — `normalize(cwd, path)`, `find_node(root, parts)`,
  `format_path(parts)`, `locate(command, session, label)`,
  `Target(label, parts, node)`.
- `session.py` — `Session(vfs=None)`: поля `vfs` и `cwd`, свойство
  `root`, методы `attach(vfs)` и `cwd_path()`.
- `vfs.py` — классы `VfsError`, `VfsNode`, `VfsFile`, `VfsDirectory`,
  `Vfs` (метод `statistics()`); функции `is_binary`, `split_path`,
  `make_directories`, `entry_mode`, `add_entry`, `build_tree`,
  `load_vfs(path)`, `format_summary`, `format_info`, `node_label`,
  `render_tree`, `format_tree`.
- `navigation.py` — `command_ls`, `command_cd`; вспомогательные
  `sort_key`, `describe_mode`, `long_row`, `format_long`,
  `render_entries`, `directory_entries`, `add_header`,
  `build_sections`.
- `text_tools.py` — `command_cat`, `command_uniq`; вспомогательные
  `read_file`, `trim_newline`, `number_lines`, `read_uniq_input`,
  `group_lines`, `is_selected`.
- `modification.py` — `command_chown`, `command_rm`; вспомогательные
  `is_valid_name`, `is_valid_spec`, `parse_owner`, `iter_nodes`,
  `last_part`, `check_removable`, `is_inside`, `drop_nested`,
  `collect_targets`, `removal_message`.
- `help_text.py` — `HELP` (словарь `HelpEntry`: использование,
  описание, ключи, примечания), `format_list(names)`,
  `format_entry(name)`.
- `commands.py` — `COMMANDS` (реестр), `execute(tokens, session)`,
  `command_vfs_info`, `command_vfs_tree`, `command_help`,
  `command_exit`, `reject_arguments`, `require_vfs`.
- `gui.py` — `get_user_name()`, `build_title()` (заголовок
  `Эмулятор - [username@hostname]`), `build_prompt(session)`
  (приглашение вида `/home/user$ `), класс `EmulatorWindow(master,
  config)` с методами `place_widgets`, `start`, `connect_vfs`, `write`,
  `on_enter`, `run_line`, `run_command`, `run_script`,
  `run_script_line`.
- `main.py` — `main()`: разбор параметров, создание окна `Tk`, цикл
  событий.
- `scripts/make_vfs.py` — `make_samples(directory)`, `entry_info(name)`,
  `write_archive(path, entries)`, `write_broken(path)`.

Чтобы добавить команду, нужна функция `(arguments, session)`,
возвращающая текст, запись в `COMMANDS` и запись в `HELP`
(соответствие проверяет тест).

Настройки интерфейса (константы `gui.py`): `OUTPUT_HEIGHT` = 24 и
`OUTPUT_WIDTH` = 80 (размер области вывода), `MIN_WINDOW_WIDTH` = 640 и
`MIN_WINDOW_HEIGHT` = 400 (минимальный размер окна), `PADDING` = 4,
`FONT` = `TkFixedFont`, `PROMPT` = `"{0}$ "` (шаблон приглашения),
`START_DELAY_MS` = 100 (задержка перед стартовым скриптом).

## 3. Команды для сборки проекта и запуска тестов

Отдельная сборка не требуется: проект написан на Python и не
использует внешних библиотек. Нужен Python 3.8 или новее с модулем
`tkinter` (в Debian или Ubuntu: `sudo apt install python3-tk`).

```bash
python3 --version
python3 -c "import tkinter"             # проверка окружения
python3 scripts/make_vfs.py data        # образцы VFS (или: make samples)
```

Запуск эмулятора:

```bash
./run.sh --vfs data/nested.zip --script scripts/emulator/stage5_all.txt   # Linux, macOS
run.bat --vfs data\nested.zip --script scripts\emulator\stage5_all.txt    # Windows
python3 -m src.main --vfs data/nested.zip     # напрямую, из корня репозитория
make run                                      # без параметров
make run-script                               # образцы + stage5_all.txt
```

Скрипты реальной ОС (в Windows — одноимённые `.bat`):

```bash
./scripts/os/test_params.sh
./scripts/os/test_stage5_all.sh        # и остальные из таблицы выше
./scripts/os/test_stage5_memory.sh
```

Запуск тестов (в том числе проверка всех стартовых скриптов без
графики):

```bash
python3 -m unittest discover -s tests -t . -v     # или: make test
```

Ожидаемый результат: `Ran 190 tests ... OK`.

### Пример 5. Команда uniq

Файл `words.txt` содержит по строке: `apple, apple, Apple, banana, cherry,
cherry, cherry, apple`. Последняя `apple` не объединяется с первыми:
`uniq`, как и в UNIX, сравнивает только соседние строки.

```
/home/user/docs$ uniq -c words.txt
      2 apple
      1 Apple
      1 banana
      3 cherry
      1 apple
/home/user/docs$ uniq -d words.txt
apple
cherry
/home/user/docs$ uniq -u words.txt
Apple
banana
apple
/home/user/docs$ uniq -ci words.txt
      3 apple
      1 banana
      3 cherry
      1 apple
/home/user/docs$ uniq -d -u words.txt
uniq: ключи -d и -u несовместимы
/home/user/docs$ uniq ../pictures/logo.png
uniq: ../pictures/logo.png: двоичный файл
```

`<тип>(<область>): <описание>`, подробности — в теле сообщения.

```
feat(vfs): добавить загрузку VFS из ZIP-архива в память
feat(navigation): реализовать логику команд ls и cd
feat(modification): добавить команды chown и rm
feat(help): добавить команду help со справкой по командам
chore(scripts): добавить скрипты этапа 5
docs(readme): описать этап 5: chown, rm, help
```
