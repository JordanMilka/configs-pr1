# Эмулятор командной оболочки (вариант 8, этапы 1–2)

## 1. Общее описание

Учебный проект по дисциплине «Конфигурационное управление».
Разрабатывается эмулятор языка оболочки ОС, работа которого
максимально похожа на работу в командной строке UNIX-подобной
системы.

**Этап 1 «REPL»** — минимальный прототип с графическим
интерфейсом: диалог с пользователем, парсер ввода и
команды-заглушки.

**Этап 2 «Конфигурация»** — эмулятор стал настраиваемым: он
принимает параметры командной строки, печатает их отладочным
выводом при запуске и умеет выполнять стартовый скрипт,
имитируя диалог с пользователем.

Что реализовано:

- графический интерфейс на библиотеке `tkinter` (входит в
  стандартную поставку Python);
- заголовок окна формируется по данным реальной ОС в формате
  `Эмулятор - [username@hostname]`;
- парсер ввода с раскрытием переменных окружения реальной ОС
  (`$HOME`, `${HOME}`);
- команды-заглушки `ls` и `cd`, команда `exit`;
- сообщения об ошибках: неизвестная команда, неверные аргументы,
  ошибка разбора строки;
- параметры командной строки `--vfs` и `--script`;
- отладочный вывод всех заданных параметров при запуске;
- выполнение стартового скрипта с остановкой на первой ошибке и
  сообщением о ней;
- скрипты реальной ОС для проверки всех параметров запуска.

Виртуальная файловая система и реальная логика команд появятся
на следующих этапах. На этапе 2 путь к VFS только принимается и
выводится на экран.

## 2. Описание всех функций и настроек

### Параметры командной строки

| Параметр | Значение | Назначение |
| --- | --- | --- |
| `--vfs ПУТЬ` | путь | Путь к физическому расположению VFS. |
| `--script ПУТЬ` | путь | Путь к стартовому скрипту эмулятора. |
| `-h`, `--help` | — | Справка по параметрам и выход. |

Оба параметра необязательны. Если параметр не задан, в отладочном
выводе он помечается текстом «не задан». При запуске эмулятор
всегда печатает значения всех параметров:

```
Параметры запуска:
  путь к VFS: data/vfs.zip
  путь к стартовому скрипту: scripts/emulator/stage2_demo.txt
```

### Стартовый скрипт эмулятора

Стартовый скрипт — текстовый файл в кодировке UTF-8, каждая
строка которого является командой эмулятора. Пустые строки и
строки, начинающиеся со знака `#`, пропускаются. При выполнении
на экране отображается и ввод (со знаком приглашения `$`), и
вывод, что имитирует диалог с пользователем. На первой ошибке
выполнение останавливается, и выводится номер проблемной строки.

Готовые скрипты лежат в `scripts/emulator/`:

| Файл | Назначение |
| --- | --- |
| `stage2_demo.txt` | Успешное выполнение всех команд-заглушек. |
| `stage2_error.txt` | Ошибка в середине скрипта и остановка. |
| `stage2_exit.txt` | Завершение работы эмулятора командой `exit`. |

### Модуль `src/config.py`

| Функция | Назначение |
| --- | --- |
| `build_parser()` | Создаёт разборщик параметров командной строки. |
| `parse_arguments(argv)` | Разбирает параметры и возвращает объект `Config`. |
| `format_value(value)` | Возвращает значение параметра или пометку «не задан». |
| `format_config(config)` | Готовит отладочный вывод всех параметров запуска. |

`Config` — именованный кортеж с полями `vfs_path` и `script_path`.
Константа `NOT_SET` задаёт текст для незаданного параметра.

### Модуль `src/script.py`

| Функция | Назначение |
| --- | --- |
| `read_script_lines(path)` | Читает строки стартового скрипта, при ошибке чтения возбуждает `ScriptError`. |
| `is_executable_line(line)` | Возвращает `False` для пустой строки и комментария. |

Константы: `COMMENT_SIGN` — знак комментария, `ENCODING` —
кодировка файла скрипта. Исключение `ScriptError` сообщает о
невозможности прочитать стартовый скрипт.

### Модуль `src/parser.py`

| Функция | Назначение |
| --- | --- |
| `is_name_symbol(symbol)` | Проверяет, допустим ли символ в имени переменной. |
| `read_plain_name(text, start)` | Читает имя переменной без фигурных скобок. |
| `read_braced_name(text, start)` | Читает имя переменной в фигурных скобках. |
| `read_variable_name(text, start)` | Выбирает способ чтения имени переменной. |
| `expand_variables(text)` | Раскрывает переменные вида `$NAME` и `${NAME}`. |
| `parse_line(line)` | Раскрывает переменные и делит строку на токены. |

Правила раскрытия переменных:

- `$NAME` — имя читается до первого символа, не являющегося
  буквой, цифрой или знаком подчёркивания;
- `${NAME}` — имя ограничено фигурными скобками;
- неизвестная переменная заменяется пустой строкой;
- одиночный знак `$` выводится без изменений;
- незакрытая фигурная скобка вызывает ошибку `ParseError`.

### Модуль `src/commands.py`

| Функция | Назначение |
| --- | --- |
| `format_stub(name, arguments)` | Формирует ответ команды-заглушки. |
| `command_ls(arguments)` | Заглушка `ls`: выводит имя команды и аргументы. |
| `command_cd(arguments)` | Заглушка `cd`: принимает не более одного аргумента. |
| `command_exit(arguments)` | Завершает работу эмулятора. |
| `execute(tokens)` | Находит команду в словаре `COMMANDS` и вызывает её. |

Исключения: `CommandError` — неизвестная команда или неверные
аргументы, `ExitRequested` — запрос на завершение работы.

Константы: `MAX_CD_ARGUMENTS` (`1`), `MAX_EXIT_ARGUMENTS` (`0`),
`COMMANDS` — словарь соответствия имени команды и обработчика.
Чтобы добавить команду, достаточно написать функцию с одним
аргументом-списком и зарегистрировать её в `COMMANDS`.

### Модуль `src/gui.py`

| Функция или метод | Назначение |
| --- | --- |
| `get_user_name()` | Возвращает имя текущего пользователя ОС. |
| `build_title()` | Формирует заголовок `Эмулятор - [username@hostname]`. |
| `EmulatorWindow.__init__(master, config)` | Создаёт виджеты и планирует запуск стартового скрипта. |
| `EmulatorWindow.place_widgets()` | Размещает поле ввода снизу, область вывода сверху. |
| `EmulatorWindow.start()` | Печатает параметры запуска и выполняет стартовый скрипт. |
| `EmulatorWindow.write(text)` | Добавляет строку в область вывода. |
| `EmulatorWindow.on_enter(event)` | Обрабатывает нажатие Enter в поле ввода. |
| `EmulatorWindow.run_line(line)` | Разбирает и выполняет строку, возвращает признак успеха. |
| `EmulatorWindow.run_command(tokens)` | Выполняет команду и выводит результат или ошибку. |
| `EmulatorWindow.run_script(path)` | Выполняет стартовый скрипт, останавливаясь на первой ошибке. |
| `EmulatorWindow.run_script_line(line)` | Показывает строку скрипта и выполняет её. |

Константы-настройки интерфейса:

| Константа | Значение | Назначение |
| --- | --- | --- |
| `OUTPUT_HEIGHT` | `24` | Высота области вывода в строках. |
| `OUTPUT_WIDTH` | `80` | Ширина области вывода в символах. |
| `MIN_WINDOW_WIDTH` | `640` | Минимальная ширина окна в пикселях. |
| `MIN_WINDOW_HEIGHT` | `400` | Минимальная высота окна в пикселях. |
| `PADDING` | `4` | Отступ виджетов от краёв окна. |
| `FONT` | `TkFixedFont` | Моноширинный шрифт области вывода и поля ввода. |
| `PROMPT` | `"$ "` | Приглашение к вводу в области диалога. |
| `START_DELAY_MS` | `100` | Задержка перед запуском стартового скрипта. |

### Модуль `src/main.py`

Функция `main()` разбирает параметры командной строки, создаёт
корневое окно `Tk`, объект `EmulatorWindow` и запускает цикл
обработки событий.

## 3. Команды для сборки проекта и запуска тестов

Отдельная сборка не требуется: проект написан на Python и не
использует внешних библиотек. Нужен Python 3.8 или новее с
модулем `tkinter`.

Проверка окружения:

```bash
python3 --version
python3 -c "import tkinter"
```

Если `tkinter` не установлен, в Debian или Ubuntu его ставят
командой `sudo apt install python3-tk`.

Запуск эмулятора:

```bash
# Linux, macOS
./run.sh
./run.sh --vfs data/vfs.zip --script scripts/emulator/stage2_demo.txt

# Windows
run.bat
run.bat --vfs data\vfs.zip --script scripts\emulator\stage2_demo.txt

# напрямую, из корня репозитория
python3 -m src.main --script scripts/emulator/stage2_demo.txt

# через Makefile
make run
make run-script
```

Запуск скриптов реальной ОС, проверяющих все параметры запуска:

```bash
# Linux, macOS
./scripts/os/test_params.sh
./scripts/os/test_script_errors.sh

# Windows
scripts\os\test_params.bat
scripts\os\test_script_errors.bat
```

Запуск тестов:

```bash
# из корня репозитория
python3 -m unittest discover -s tests -t . -v

# через Makefile
make test
```

Ожидаемый результат: `Ran 26 tests ... OK`.

## 4. Примеры использования

### Пример 1. Запуск без параметров

```
Эмулятор оболочки. Доступны команды: ls, cd, exit.
Параметры запуска:
  путь к VFS: не задан
  путь к стартовому скрипту: не задан
$ ls
ls: аргументы отсутствуют
$ ls -l /etc
ls: -l /etc
$ cd /home
cd: /home
```

### Пример 2. Раскрытие переменных окружения

```
$ ls $HOME
ls: /home/ivanov
$ cd ${HOME}
cd: /home/ivanov
$ ls ${HOME}/documents
ls: /home/ivanov/documents
$ ls $NO_SUCH_VARIABLE
ls: аргументы отсутствуют
$ ls price $ 5
ls: price $ 5
```

### Пример 3. Обработка ошибок ввода

```
$ pwd
pwd: команда не найдена
$ cd one two
cd: слишком много аргументов
$ exit now
exit: команда не принимает аргументов
$ ls ${HOME
ошибка разбора: не закрыта фигурная скобка в имени переменной
```

### Пример 4. Выполнение стартового скрипта

Команда запуска:

```bash
python3 -m src.main --vfs data/vfs.zip \
    --script scripts/emulator/stage2_demo.txt
```

Диалог в окне эмулятора:

```
Эмулятор оболочки. Доступны команды: ls, cd, exit.
Параметры запуска:
  путь к VFS: data/vfs.zip
  путь к стартовому скрипту: scripts/emulator/stage2_demo.txt
$ ls
ls: аргументы отсутствуют
$ ls -l /etc
ls: -l /etc
$ cd /home
cd: /home
$ ls $HOME
ls: /home/ivanov
$ cd ${HOME}
cd: /home/ivanov
$ ls $NO_SUCH_VARIABLE
ls: аргументы отсутствуют
Стартовый скрипт выполнен.
```

### Пример 5. Ошибка во время исполнения стартового скрипта

Команда запуска:

```bash
python3 -m src.main --script scripts/emulator/stage2_error.txt
```

Диалог в окне эмулятора:

```
Параметры запуска:
  путь к VFS: не задан
  путь к стартовому скрипту: scripts/emulator/stage2_error.txt
$ ls $HOME
ls: /home/ivanov
$ cd one two
cd: слишком много аргументов
Скрипт остановлен из-за ошибки в строке 3.
```

Строки после ошибочной не выполняются, работа продолжается в
интерактивном режиме.

### Пример 6. Стартовый скрипт не найден

```
Параметры запуска:
  путь к VFS: не задан
  путь к стартовому скрипту: scripts/emulator/none.txt
ошибка стартового скрипта: не удалось прочитать файл
scripts/emulator/none.txt: [Errno 2] No such file or directory
```

## Оформление коммитов

История коммитов ведётся по спецификации Conventional Commits:
`<тип>(<область>): <описание>`.

Примеры коммитов:

```
feat(parser): добавить раскрытие переменных окружения
feat(commands): добавить заглушки ls, cd и команду exit
feat(gui): добавить окно эмулятора с полем ввода команд
fix(gui): не обрезать поле ввода при изменении размера окна
feat(config): добавить параметры командной строки vfs и script
feat(script): добавить выполнение стартового скрипта
docs(readme): описать параметры запуска и стартовые скрипты
```
