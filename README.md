# Эмулятор командной оболочки (вариант 8, этапы 1–4)

## 1. Общее описание

Учебный проект по дисциплине «Конфигурационное управление».
Разрабатывается эмулятор языка оболочки ОС, работа которого
максимально похожа на работу в командной строке UNIX-подобной
системы.

**Этап 1 «REPL»** — минимальный прототип с графическим
интерфейсом: диалог с пользователем, парсер ввода и команда `exit`.

**Этап 2 «Конфигурация»** — эмулятор принимает параметры
командной строки, печатает их отладочным выводом при запуске и
умеет выполнять стартовый скрипт, имитируя диалог с пользователем.

**Этап 3 «VFS»** — подключена виртуальная файловая система. Она
загружается из ZIP-архива целиком в память: ничего не
распаковывается на диск, архив не изменяется. Двоичные файлы
хранятся в виде строк base64. Ошибки загрузки (файл не найден,
неверный формат) сообщаются пользователю.

**Этап 4 «Основные команды»** — реализована логика `ls` и `cd`,
добавлены команды `uniq` и `cat`. Приглашение к вводу показывает
текущий каталог VFS.

Что реализовано:

- графический интерфейс на библиотеке `tkinter` (входит в
  стандартную поставку Python);
- заголовок окна формируется по данным реальной ОС в формате
  `Эмулятор - [username@hostname]`;
- парсер ввода с раскрытием переменных окружения реальной ОС
  (`$HOME`, `${HOME}`);
- команды `ls`, `cd`, `cat`, `uniq`, `exit` и служебные команды
  `vfs-info` и `vfs-tree`;
- сообщения об ошибках: неизвестная команда, неверные аргументы и
  ключи, несуществующие пути, ошибка разбора строки, ошибка
  загрузки VFS;
- параметры командной строки `--vfs` и `--script`;
- отладочный вывод всех заданных параметров при запуске;
- выполнение стартового скрипта с остановкой на первой ошибке и
  сообщением о ней;
- скрипты реальной ОС для проверки параметров запуска, разных
  вариантов VFS и всех команд.

Команды `chown`, `rm` и `help` появятся на следующем этапе.

## 2. Описание всех функций и настроек

### Параметры командной строки

| Параметр | Значение | Назначение |
| --- | --- | --- |
| `--vfs ПУТЬ` | путь | Путь к ZIP-архиву с VFS. |
| `--script ПУТЬ` | путь | Путь к стартовому скрипту эмулятора. |
| `-h`, `--help` | — | Справка по параметрам и выход. |

Оба параметра необязательны. Если параметр не задан, в отладочном
выводе он помечается текстом «не задан». При запуске эмулятор
всегда печатает значения всех параметров:

```
Параметры запуска:
  путь к VFS: data/nested.zip
  путь к стартовому скрипту: scripts/emulator/stage4_all.txt
```

Без параметра `--vfs` файловая система считается пустой: в ней
есть только корень `/`.

### Приглашение к вводу

Приглашение показывает текущий каталог VFS: `/$` в корне,
`/home/user$` после `cd /home/user`. При запуске и после
подключения VFS текущий каталог — корень.

### Команды эмулятора

| Команда | Описание |
| --- | --- |
| `ls [-l] [-a] [путь...]` | Содержимое каталогов и сведения о файлах. |
| `cd [путь]` | Смена текущего каталога. |
| `cat [-n] файл...` | Вывод содержимого файлов. |
| `uniq [-c] [-d] [-u] [-i] файл` | Удаление подряд идущих повторяющихся строк. |
| `vfs-info` | Служебная: источник, число каталогов и файлов, размер, вложенность. |
| `vfs-tree` | Служебная: дерево каталогов и файлов VFS. |
| `exit` | Завершает работу эмулятора. |

Все команды только читают данные из памяти и ничего не изменяют.
Ключи записываются одной буквой после дефиса и объединяются
(`-la`); `--` заканчивает список ключей. Длинные ключи (`--all`) не
поддерживаются.

**ls** — без операндов показывает текущий каталог, иначе — указанные
пути. Имена выводятся в строку через два пробела, по алфавиту без
учёта регистра. Имена, начинающиеся с точки, скрыты.

| Режим | Результат |
| --- | --- |
| `ls` | Текущий каталог. |
| `ls путь` | Указанный каталог; для файла — его имя. |
| `ls -l` | Подробный список: тип и права, владелец, группа, размер в байтах, время изменения, имя. |
| `ls -a` | Дополнительно скрытые имена, а также `.` и `..`. |
| `ls -la` | Оба ключа вместе. |
| `ls путь1 путь2` | Файлы списком, затем каждый каталог с заголовком `путь:`. |

**cd** — без аргумента переходит в корень. Поддерживает абсолютные
(`/home/user`) и относительные пути, части `.` и `..`; выше корня
подняться нельзя, при этом ошибки нет. При успехе ничего не
выводит. Аргумент один: `cd a b` — ошибка.

**cat** — склеивает содержимое файлов в порядке аргументов, как в
UNIX. Режимы: один файл, несколько файлов, `-n` (сквозная
нумерация строк). Двоичные файлы выводятся в виде base64, в котором
они хранятся в VFS. Если хотя бы один файл не найден, ничего не
выводится. Без операндов — ошибка (чтения из стандартного ввода нет).

**uniq** — как в UNIX, сравнивает только соседние строки. Режимы:

| Режим | Результат |
| --- | --- |
| `uniq файл` | Подряд идущие одинаковые строки схлопываются. |
| `-c` | Перед строкой выводится число повторов. |
| `-d` | Только повторяющиеся строки (по одной на группу). |
| `-u` | Только неповторяющиеся строки. |
| `-i` | Регистр не учитывается. |
| `-ci`, `-cd` | Ключи можно объединять; `-d` и `-u` вместе — ошибка. |

Двоичные файлы `uniq` не обрабатывает.

**Сообщения об ошибках** (`КОМАНДА` — имя команды):

| Ситуация | Сообщение |
| --- | --- |
| Неизвестная команда | `КОМАНДА: команда не найдена` |
| Путь не существует | `КОМАНДА: путь: нет такого файла или каталога` |
| `cd` в файл | `cd: путь: не является каталогом` |
| `cat` или `uniq` для каталога | `КОМАНДА: путь: является каталогом` |
| Неверный ключ | `КОМАНДА: неверный ключ -- 'x'` |
| `cd` с несколькими аргументами | `cd: слишком много аргументов` |
| `cat` или `uniq` без файла | `КОМАНДА: не указан файл` |
| `uniq` с двумя файлами | `uniq: лишний операнд 'путь'` |
| `uniq -d -u` | `uniq: ключи -d и -u несовместимы` |
| `uniq` для двоичного файла | `uniq: путь: двоичный файл` |
| Аргументы у `exit`, `vfs-info`, `vfs-tree` | `КОМАНДА: команда не принимает аргументов` |
| Команда VFS без `--vfs` | `КОМАНДА: VFS не подключена, задайте параметр --vfs` |
| Ошибка разбора строки | `ошибка разбора: ...` |

Переменные окружения реальной ОС раскрываются в любой команде,
в том числе в путях (`cd $EMU_DIR`):

- `$NAME` — имя читается до первого символа, не являющегося
  буквой, цифрой или знаком подчёркивания;
- `${NAME}` — имя ограничено фигурными скобками;
- неизвестная переменная заменяется пустой строкой;
- одиночный знак `$` выводится без изменений;
- незакрытая скобка, пустое имя `${}` или недопустимые символы в
  имени (`${A B}`) вызывают ошибку разбора.

### Виртуальная файловая система

Источник VFS — ZIP-архив, путь к которому задаётся параметром
`--vfs`. Правила загрузки:

- архив открывается только на чтение и читается в память целиком,
  распаковка на диск не выполняется, архив не изменяется;
- каталоги создаются по путям записей, отдельные записи о
  каталогах не обязательны; пустой архив допустим;
- текстовый файл (корректный UTF-8 без нулевых байтов) хранится
  строкой, двоичный — строкой base64; в `vfs-tree` двоичные файлы
  помечены `[двоичный]`;
- права доступа берутся из атрибутов Unix записи архива (для
  архивов без них — `rw-r--r--` у файлов и `rwxr-xr-x` у
  каталогов), время изменения — из даты записи; владелец и группа
  по умолчанию — `root`;
- абсолютные пути, пути с `..`, повторяющиеся пути и совпадение
  имени файла с именем каталога считаются ошибкой формата.

Ошибки загрузки выводятся в окно эмулятора:

| Ситуация | Сообщение |
| --- | --- |
| Файл не найден | `ошибка загрузки VFS: файл не найден: ПУТЬ` |
| Неверный формат | `ошибка загрузки VFS: неверный формат архива ПУТЬ: ...` |
| Путь указывает на каталог или файл не читается | `ошибка загрузки VFS: не удалось прочитать ПУТЬ: ...` |
| Небезопасный путь, дубликат, конфликт имён | `ошибка загрузки VFS: небезопасный путь в архиве: ...` |

После ошибки эмулятор продолжает работу в интерактивном режиме
без VFS. Стартовый скрипт при этом не выполняется, о чём выводится
сообщение: его команды рассчитаны на загруженную VFS.

### Образцы VFS

`python3 scripts/make_vfs.py [КАТАЛОГ]` создаёт в каталоге (по
умолчанию `data`) файлы. У всех записей одинаковое время
изменения `2026-01-15 10:30`, чтобы вывод `ls -l` не зависел от
даты запуска.

| Файл | Содержимое |
| --- | --- |
| `empty.zip` | Пустой архив. |
| `minimal.zip` | Один файл `hello.txt`. |
| `several.zip` | Четыре файла в корне (один двоичный, `fruits.txt` с повторами) и пустой каталог. |
| `nested.zip` | Шесть уровней вложенности, скрытый `.profile`, `words.txt` с повторами, двоичный `logo.png`. |
| `broken.zip` | Текстовый файл, а не архив, — для проверки ошибки формата. |

### Стартовый скрипт эмулятора

Стартовый скрипт — текстовый файл в кодировке UTF-8, каждая
строка которого является командой эмулятора. Пустые строки и
строки, начинающиеся со знака `#`, пропускаются. При выполнении
на экране отображается и ввод (с приглашением), и вывод, что
имитирует диалог с пользователем. На первой ошибке выполнение
останавливается, и выводится номер строки файла.

Готовые скрипты лежат в `scripts/emulator/`:

| Файл | Назначение |
| --- | --- |
| `stage2_demo.txt` | `ls`, `cd` и неизвестная переменная; работает и без VFS. |
| `stage2_error.txt` | Ошибка в середине скрипта и остановка. |
| `stage2_exit.txt` | Завершение работы командой `exit`. |
| `stage3_all.txt` | Команды этапов 1–3 в рабочих режимах (запускать с `data/nested.zip`). |
| `stage3_empty.txt`, `stage3_minimal.txt` | `vfs-info` и `vfs-tree` для пустого и минимального образцов. |
| `stage3_several.txt`, `stage3_nested.txt` | `vfs-info` и `vfs-tree` для образцов с файлами и вложенностью. |
| `stage3_error_unknown.txt` | Ошибка: неизвестная команда. |
| `stage3_error_arguments.txt` | Ошибка: неверные аргументы. |
| `stage3_error_parse.txt` | Ошибка разбора строки (`${}`). |
| `stage3_error_no_vfs.txt` | Ошибка: команда VFS без параметра `--vfs`. |
| `stage4_all.txt` | Все команды этапа 4 во всех режимах (запускать с `data/nested.zip`). |
| `stage4_several.txt` | Команды этапа 4 на `data/several.zip`. |
| `stage4_env.txt` | Переменные окружения `EMU_DIR` и `EMU_FILE` в путях. |
| `stage4_errors/*.txt` | По скрипту на ошибку: `ls_missing`, `ls_option`, `cd_missing`, `cd_file`, `cat_*`, `uniq_*`. |

Так как скрипт останавливается на первой ошибке, каждая
ошибочная ситуация вынесена в отдельный скрипт `*_error_*` или
`stage4_errors/*`. Скрипты с рабочими режимами заканчиваются
командой `exit`.

### Скрипты реальной ОС

Лежат в `scripts/os/`, для каждого есть версия `.sh` (Linux,
macOS) и `.bat` (Windows). Все они сначала создают образцы VFS,
затем запускают эмулятор.

| Скрипт | Что проверяет |
| --- | --- |
| `test_params` | Все сочетания параметров `--vfs` и `--script`. |
| `test_script_errors` | Ошибки стартового скрипта: остановка, файл не найден, `exit`. |
| `test_vfs_minimal` | Пустой архив и архив из одного файла. |
| `test_vfs_several` | VFS с несколькими файлами, пустым каталогом, двоичным файлом. |
| `test_vfs_nested` | VFS с вложенностью до шести уровней. |
| `test_vfs_errors` | Файл не найден, неверный формат, каталог вместо архива, команда VFS без `--vfs`. |
| `test_stage3_all` | Все команды этапов 1–3: `stage3_all.txt` и все `stage3_error_*`. |
| `test_stage4_all` | Все режимы `ls`, `cd`, `cat`, `uniq` на `nested.zip` и `several.zip`. |
| `test_stage4_env` | Задаёт `EMU_DIR` и `EMU_FILE` в реальной ОС и использует их в путях. |
| `test_stage4_errors` | Запускает по очереди все скрипты из `stage4_errors`. |

Если стартовый скрипт эмулятора не завершается командой
`exit`, окно остаётся открытым — закройте его, чтобы перейти к
следующему шагу.

### Модуль `src/config.py`

| Функция | Назначение |

| Функция в `options.py` | Назначение |
| --- | --- |
| `read_cluster(name, argument, allowed)` | Читает буквы ключей из аргумента вида `-la`, отклоняет неизвестные. |
| `parse_options(name, arguments, allowed)` | Делит аргументы на множество ключей и список операндов. |

### Модуль `src/paths.py`

| Элемент | Назначение |
| --- | --- |
| `normalize(cwd, path)` | Приводит абсолютный или относительный путь к списку имён от корня. |
| `find_node(root, parts)` | Находит узел VFS или возвращает `None`. |
| `format_path(parts)` | Собирает путь вида `/home/user`. |

### Модуль `src/session.py`

Класс `Session(vfs=None)` хранит состояние сеанса: `vfs` —
подключённая VFS или `None`, `cwd` — список имён текущего каталога.
Свойство `root` возвращает корень VFS (пустой каталог, если VFS нет),
`attach(vfs)` подключает VFS и переходит в корень, `cwd_path()`
возвращает путь текущего каталога.

### Модуль `src/main.py` и скрипт `scripts/make_vfs.py`

`main()` в `src/main.py` разбирает параметры командной строки,
создаёт корневое окно `Tk`, объект `EmulatorWindow` и запускает
цикл событий. `make_samples(directory)` в `scripts/make_vfs.py`
создаёт образцы VFS, `entry_info(name)` готовит запись с правами и
фиксированным временем, `write_archive(path, entries)` пишет один
ZIP-архив, `write_broken(path)` — файл неверного формата.

## 3. Команды для сборки проекта и запуска тестов

Отдельная сборка не требуется: проект написан на Python и не
использует внешних библиотек. Нужен Python 3.8 или новее с
модулем `tkinter`.

Проверка окружения:

```bash
python3 --version
python3 -c "import tkinter"
```

Если `tkinter` не установлен, в Debian или Ubuntu его ставят
командой `sudo apt install python3-tk`.

Создание образцов VFS (нужны для запуска с `--vfs`):

```bash
python3 scripts/make_vfs.py data
# или
make samples
```

Запуск эмулятора:

```bash
# Linux, macOS
./run.sh
./run.sh --vfs data/nested.zip --script scripts/emulator/stage4_all.txt

# Windows
run.bat
run.bat --vfs data\nested.zip --script scripts\emulator\stage4_all.txt

# напрямую, из корня репозитория
python3 -m src.main --vfs data/nested.zip

# через Makefile
make run
make run-script
```

Запуск скриптов реальной ОС (в Windows — одноимённые `.bat`):

```bash
./scripts/os/test_params.sh
./scripts/os/test_script_errors.sh
./scripts/os/test_vfs_minimal.sh
./scripts/os/test_vfs_several.sh
./scripts/os/test_vfs_nested.sh
./scripts/os/test_vfs_errors.sh
./scripts/os/test_stage3_all.sh
./scripts/os/test_stage4_all.sh
./scripts/os/test_stage4_env.sh
./scripts/os/test_stage4_errors.sh
```

Запуск тестов (в том числе проверка всех стартовых скриптов без
графики):

```bash
# из корня репозитория
python3 -m unittest discover -s tests -t . -v

# через Makefile
make test
```

Ожидаемый результат: `Ran 137 tests ... OK`.

## Оформление коммитов

История коммитов ведётся по спецификации Conventional Commits:
`<тип>(<область>): <описание>`, подробности — в теле сообщения.

Примеры коммитов:

```
feat(parser): добавить раскрытие переменных окружения
feat(config): добавить параметры командной строки vfs и script
feat(vfs): добавить загрузку VFS из ZIP-архива в память
feat(navigation): реализовать логику команд ls и cd
feat(text-tools): добавить команды cat и uniq
chore(scripts): добавить скрипты этапа 4 и обновить скрипты этапов 2-3
docs(readme): описать этап 4
```
